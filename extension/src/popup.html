UniFi Live

Live clients and AP telemetry on your floor plans. Read-only — GETs only, no writes, ever.

UniFi console

What this does

Draws live clients and AP telemetry onto the InnerSpace floor plan inside your console. On a LAN console it reads the console's own API directly and needs nothing else configured.

Bridge optional

When do I need a bridge?

On a WebRTC-relayed unifi.ui.com session the page has no HTTP API to read, so a unifi-hamina-live instance is the only way to get data. A LAN console or an HTTP-proxied unifi.ui.com session needs none.

One bridge polls one console, so this is stored per console. Test it before relying on it — pointing at a bridge covering a different console looks healthy and draws nothing.

Hamina overlay optional

What this does

Shows the bridge's live UniFi data as a panel on Hamina's map. Nothing is sent to Hamina — the panel is built in your browser from Hamina's own map API plus the bridge.

Use us.hamina.com or eu.hamina.com, whichever you sign in to.

The bridge decides which console the panel reads. With one console it is picked for you; with two there is nothing to guess from, so choose it here. Pointing at the wrong one is quiet and convincing — every AP reports not in UniFi, which reads as a name-matching problem rather than a wrong console.
